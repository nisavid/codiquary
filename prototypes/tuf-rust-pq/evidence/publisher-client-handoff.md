This is a source-literal mismatch, not a recomputed hash result. The publisher bytes are identified in the target construction, but no target bytes corresponding to the interrupted-refresh client descriptors are identified in the inspected interrupted-refresh fixture source, and the [interrupted-refresh observation](https://github.com/nisavid/codiquary/blob/830828abd6499e70831944c529960078ac88df53/prototypes/tuf-rust-pq/evidence/issue-22-interrupted-refresh.md#L12-L19) states that the experiment never fetches target content.

The inspected sources therefore do not establish one coherent publisher-to-client target binding. [Prototype the Rust RFC 9980 TUF implementation path](https://github.com/nisavid/codiquary/issues/16) needs one explicitly selected publisher/client fixture bound to exact target bytes before [Prototype the TUF consumer and transport boundary](https://github.com/nisavid/codiquary/issues/17) can consume it. This investigation inspected source only; it did not run tests, recompute hashes, verify signatures, load a client, or qualify transport, retained policy, lifecycle, or production behavior.
